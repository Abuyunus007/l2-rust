Generators in `java-vectors` that run the **real** L2JMobius stat code and formulas and write JSON
vectors, so M4-STAT-01, M4-COMBAT-01 and M4-REGEN-01 can be checked number for number (D-41).

## Requirements
1. Bootstrap the minimum of the real server in-process **without any database and without network**: configs from `C:\l2-rust\l2jmobius\dist\game\config` (read-only), the datapack loaders the stat code needs. Find the smallest set that works; document it in the README. If a constructor insists on the DB (`Player.create`, IdManager), find the no-DB path (e.g. the `Player(int objectId, PlayerTemplate, String account, PlayerAppearance)` style constructors) or report.
2. Stat vectors: for a fixed list of cases print every `UserInfo` number (STR..MEN, P.Atk, P.Def, M.Atk, M.Def, accuracy, evasion, crit, P.Atk speed, M.Atk speed, run/walk/swim speeds, max HP/MP/CP, max load, attack range) for:
   - players: each starting class at level 1, a few classes at 20/40/52/76/85, naked; then with a fixed gear set (weapon, armor set pieces, jewels, shield), with enchant levels 0/3/6/16, with the class's passive skills at their tree level for that character level;
   - NPCs: 30 NPC ids (monsters, raid bosses, guards, gatekeepers incl. 31033) as spawned.
   The inputs (class, level, item ids + enchant, skill ids + levels, NPC id) are in the JSON next to the outputs.
3. Formulas use `Rnd` (ThreadLocalRandom). Put a harness `org.l2jmobius.commons.util.Rnd` on the classpath **before** the L2J sources (same API, no change to the Java tree) that replays a scripted list of values and records every call (`method`, `bound`, returned value). Each formula vector stores the scripted values, so Rust replays the same draws.
4. Formula vectors: `calcHitMiss`, `calcCrit`, `calcShldUse`, `calcPhysDam` (no skill: normal attack; crit on/off; shield fail/succeed/perfect; soulshot off/on), `calcPAtkSpd`/attack timing used by `Creature.doAttack`, `calcAtkBreak`, `calcHpRegen`/`calcMpRegen`/`calcCpRegen`, `calcLvlBonusMod` and the level-diff penalties; attacker/target pairs from the stat cases (player vs monster, monster vs player).
5. Deterministic output (two runs = identical bytes), same JSON conventions as the README.
