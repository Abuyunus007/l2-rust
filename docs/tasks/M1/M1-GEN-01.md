## Goal
A `codegen` binary that parses Java enum tables and writes Rust into `src/generated/`, plus a CI check that the output is current. First target: game opcode tables. The packet proxy needs these to name packets (M1-PROXY-02).

## Java source (the spec)
Base: `C:\l2-rust\l2jmobius\java\org\l2jmobius\gameserver\network\`
- `ClientPackets.java`: `NAME(0xNN, Class::new, ConnectionState...)`
- `ExClientPackets.java`: same with `u16` ex ids (prefix 0xD0)
- `ServerPackets.java`: server opcodes (check how ex server packets are encoded: id + ex id)

## Reference implementation to copy
none (this card creates it)

## Files
Create:
- `crates/codegen/{Cargo.toml,src/main.rs,src/java_enum.rs,src/targets/opcodes.rs}`
- `crates/l2-protocol-game/{Cargo.toml,src/lib.rs,src/generated/mod.rs,src/generated/opcodes.rs}` (crate created early, only opcode tables for now)
Modify:
- `.github/workflows/ci.yml`: a step that runs `cargo run -p codegen -- all --check` (fails when the output differs)

## Requirements
1. `cargo run -p codegen -- opcodes` reads the Java files from `C:\l2-rust\l2jmobius` (path from the `L2J_ROOT` env var, default `C:\l2-rust\l2jmobius`). With `--check` it compares instead of writing.
2. **CI has no Java source.** The `--check` step must be skipped when `L2J_ROOT` doesn't exist (print a notice). The generated files are committed.
3. Output: `pub enum ClientOpcode`, `ExClientOpcode`, `ServerOpcode` (with numeric values), `fn name(self) -> &'static str`, `fn from_id(..) -> Option<Self>`, and the allowed connection states as a `&'static [ConnectionState]` (also a generated enum: CONNECTED, DISCONNECTED, CLOSING, AUTHENTICATED, ENTERING, IN_GAME).
4. Header `// @generated by codegen — do not edit`. Deterministic, formatted output (run `prettyplease` or generate already-formatted code; `cargo fmt --check` must pass).
5. The parser is a small, documented line parser (no full Java parser). It fails loudly on lines it can't understand.

## Out of scope
- SystemMessageId/NpcStringId, configs, packet layouts (M2).

## Tests
- Parser unit tests with sample lines (normal, multi-state, `null` supplier, ex ids).
- A test that the counts match: 170 client, 144 ex client, 485 server ids (numbers from `docs/analysis/02-network-crypto.md`; if the real counts differ, report it instead of changing the test silently).
