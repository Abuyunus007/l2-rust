## Goal
A `login-server` binary that starts like the Java one (config, logging, DB, key pools, IP bans, scheduled restart, exit codes) and shuts down cleanly. No listeners yet. Those are LS-02 and LS-04.

## Requirements
1. CLI (`clap`): `--config-dir` (default `./config`), `--data-dir` (default `./data`), `--root` (working dir like the Java dist folder). Defaults work when started from a copy of `dist/login`.
2. Logging with `tracing`: console + rolling file in `./log/` (Java writes `log/`). Log lines for the same startup events Java logs ("Cached 10 KeyPairs...", "Loaded N IP Bans.").
3. `LoginState` (shared, `Arc`): config, DB pool, key pools (random pick per client/GS, as Java), server names, banned IPs map with expiry (`isBannedAddress` incl. the `a.b.c.0`, `a.b.0.0`, `a.0.0.0` wildcard lookups and expiry removal: port it exactly), failed-attempt counters, login status (`AUTO`/`GOOD`/`NORMAL`/`DOWN`/`GM_ONLY`).
   This is a **server process**, not the game world: `Arc` + `Mutex`/`DashMap` is fine here (D-10 applies to game state).
4. Restart: `LoginRestartSchedule`/`LoginRestartTime` → exit code 2 after N hours. SIGINT/Ctrl-C → graceful exit 0. A fatal init error → exit 1.
5. RSA key generation runs on a blocking thread (`spawn_blocking`) so startup stays responsive.
