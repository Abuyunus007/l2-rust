## Requirements
1. All randomness is fixed: use explicit keys/inputs (seeded `java.util.Random(…)`), never `Rnd`.
2. Vector files (bytes as lowercase hex strings):
   - `crypto_blowfish.json`: key (16, 22 incl. NUL, 40 bytes), plaintext blocks → `encryptBlock`/`decryptBlock` output
   - `crypto_newcrypt.json`: `appendChecksum` / `verifyChecksum` (valid + corrupted), `encXORPass` with given key, `crypt`/`decrypt` multi-block
   - `crypto_login_encryption.json`: LoginEncryption first-packet (static key) with fixed XOR key*, and session-key encrypt/decrypt for payload sizes 1..40. *If `Rnd.nextInt()` can't be injected, compute it by calling `NewCrypt.encXORPass` + static `NewCrypt` the same way and document that.
   - `crypto_scrambled_modulus.json`: fixed 1024-bit moduli (incl. one whose `toByteArray()` has a leading 0x00) → scrambled bytes
   - `crypto_rsa_nopadding.json`: fixed RSA-1024 key (n, e, d hex) + 128-byte plaintext → ciphertext, and a 512-bit key for the GS link
   - `crypto_game_xor.json`: `Encryption` with fixed key: a sequence of 5 packets of various sizes, encrypt and decrypt, showing the key evolution (the first encrypt call only enables)
3. Each file contains `"source": "<java class/method>"` and `"generated_by": "java-vectors"` fields.
4. Running the build script twice gives byte-identical JSON.
