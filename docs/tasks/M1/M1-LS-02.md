## Requirements
1. Per connection: pick an RSA pair + BF key, random session id, send `Init` (first packet, static key), state machine CONNECTED → AUTHED_GG → AUTHED_LOGIN. Wrong-state packets are ignored.
2. RequestAuthLogin: RSA-decrypt on a blocking thread, credentials via `credentials_from_decrypted`, then the Java logic in the same order with the same results (`LoginFail` reasons, `AccountKicked(PERMANENTLY_BANNED)`, kicking an old LS session, and on ALREADY_ON_GS sending a kick to that GS through a `GsLinks` trait that LS-04 implements; stub it here).
3. On success: `SessionKey` with 4 random ints, mark authed, request characters from the GSes (through the same trait), send `LoginOk` (ShowLicence) or hand over to the server list (LS-03 provides `build_server_list`; until then, a minimal version without char info is OK and marked `// TODO(M1-LS-03)`).
4. Flood protection like `FloodProtectorListener` (FastConnectionLimit/NormalConnectionTime/FastConnectionTime/MaxConnectionPerIP).
5. Disconnect cleanup like `onDisconnection` (without Java's `Thread.sleep(1000)`; replace with the equivalent ordering guarantee and comment why).
