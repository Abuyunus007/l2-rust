## Goal
When a server exits or crashes, the Servers view shows **why**, in plain words. Today it only says "crashed, exit code 1".

1. **The supervisor keeps the last 30 log lines of each server.** It already buffers the logs; take them from there. On an exit, it adds them to the `ServerStatus`/`ServerStateChanged` event as `last_error`: the last ERROR or FATAL line, or else the last line.
2. **The Servers view shows that line under the server**, with a "Show log" button that jumps to the Logs view filtered to that server.
3. **Known causes get a hint.** Map the common startup errors to a sentence:
   - a database authentication problem (`unknown authentication plugin`, `Access denied`) becomes "Database login failed: check Login/Password in config/Database.ini (the GUI's Config view)";
   - a port in use becomes "port N is used by another program";
   - a missing datapack or geodata becomes "check DatapackRoot / GeoDataPath".
