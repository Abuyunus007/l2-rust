## Goal
Give the game server's admin endpoint (`Admin.ini`) the functions a GM needs. The supervisor relays them and the GUI shows them.

1. **Players view.**
   - Online players: name, level, class, clan, account and location. The IP only on demand.
   - Refresh and search.
   - Actions on a selected player. They use the same code as the matching `//` commands (Java `AdminKick` and `AdminPunishment`):
     - **Kick** (`//kick`).
     - **Jail** for a number of minutes (`//jail`).
     - **Ban character**, **ban account** or **chat ban**, with minutes and a reason (`//ban_char`, `//ban_acc`, `//ban_chat`).
     - **Teleport to a town.**
     - **Private message** sent as "[GM]".
2. **Announce.** A normal or a critical announcement to all players (Java `//announce` and `//critannounce`).
3. **Console.**
   - A text field that runs any admin command (a `//` command without the slashes) as a virtual GM with the highest access level.
   - Show the answer below it: the system messages, and any html as plain text.
   - Write it to the GM audit log (`log/gmaudit`) as Java does for GMs, with "GUI" as the actor.
4. **Shutdown or restart with a countdown.**
   - A seconds field and an abort button.
   - Use the Java shutdown announcements (Java `Shutdown`): the "The server is shutting down in N seconds" system messages and the abort message.
   - Use the same code path as `//server_shutdown`, `//server_restart` and `//server_abort`.
5. **Server info.** Uptime, online count, memory, threads and tick time: what `//serverinfo` shows.

Every world action goes through the world's command channel (D-15: no DB call in a tick). The punishment rows go through the outbox, as they already do.
