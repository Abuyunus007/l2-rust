## Goal
(1) Crest ids (the NOTE in `clan/crest.rs`): both servers take `max(crest_id) + 1`, so two new crests in one session collide. Java never takes an id below the max it read at its start, so Kain takes a **free id below the current maximum**: at `createCrest` Kain asks the store for the used crest ids (D-15 request/answer; the crest is set when the answer comes), takes the lowest free id > 0, and falls back to `max + 1` (logged) only when there is no gap; a failed insert (primary key) retries once with a fresh read. Note the client crest cache caveat in a comment. (2) The clan hall auction list and a bid re-read the auction rows before they are shown or acted on (D-50), like SYNC-01 does for mail. (3) `FOLLOW-UP(M7-CH-01, M7-FORT-01)` in `target.rs`: the clan hall and fortress door confirmation dialogs (`ConfirmDlg` to open/close a door for the owner clan, Java `Door.onAction`). (4) `FOLLOW-UP(zones)` in `siege/npcs.rs`: `SwampZone` and `DamageZone` (the castle traps the chamberlain upgrades), with their castle link and the trap upgrade level.
