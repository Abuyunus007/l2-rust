## Goal
A CLI tool `l2-loadtest` (new bin crate) that logs in N bot clients through the real login server and game server and plays a simple loop, to measure the server.

1. **Each bot** goes through a full login: login, server list, game server, character create (or reuse), enter world. Then it loops: walk randomly in a town, chat sometimes, target and attack a monster near a starting zone, restart now and then.
2. **Options:**
   - `--login host:port`, `--count N`, `--ramp per-second`, `--duration`;
   - `--accounts prefix` (accounts `prefix0001..`, created through `AutoCreateAccounts` on a test server);
   - `--report file`.
3. **Measures:**
   - connect and login times;
   - packets per second;
   - errors and disconnects;
   - from the game server's admin endpoint: tick time (average, p99), online count and memory, sampled every 5 s (add `TickStats` to `GameStatus` if it is not there).
4. **Report:** a summary table and a CSV of the samples.
5. **Runbook:** `docs/runbooks/m9-loadtest.md`.
   - It covers 2000 bots against a **test** setup only: its own database and ports, never the real server.
   - It states what the server needs to pass: tick p99 under 50 ms, no disconnects.

## Requirements
- Tests run the tool against an in-process login server and game server on port 0 with 20 bots for a few seconds (the e2e harness), with no database.
- The tool refuses to run when `--login` points at port 2106 unless `--i-know-this-is-a-test-server` is given.
