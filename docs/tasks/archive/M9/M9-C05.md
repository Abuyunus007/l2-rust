## Rules for every custom feature (D-57)
1. Port each feature exactly as Java, switched by the keys of its `config/Custom/<Name>.ini`. Use the same keys and the same defaults: every feature is **off by default**, as in Java.
2. Before you start, look for what already exists. Run `grep -rn <Name> crates` and check the generated config structs in `l2-config`. Several features are partly there already (config read, a few hooks). Finish those rather than writing them a second time.
3. Game logic belongs in `l2-world`, as small modules under `crates/l2-world/src/custom/` (one file per feature). Scripts from `data/scripts/custom/` go into `crates/l2-scripts/src/custom/<folder>/`, following `docs/design/scripts.md`.
4. Tables: use the same schema as Java. A table that the custom feature needs and that `dist/db_installer/sql` does not have yet goes into the installer too, by changing `tools/sync-dist.py`, never `dist/` by hand.
5. Side by side (D-39, D-53): writes a custom feature makes for every account or as a global action (for example premium expiry, faction balance, fake players' rows) only happen with `CycleDatabaseWrites`. Per-player rows are written as usual.
6. Tests: for each feature, one test with the switch off (nothing changes) and one with it on (the Java behaviour).
