## Goal
`l2-db`: an sqlx MySQL pool built from `DatabaseConfig`, and a `LoginRepository` with every query the Java login server runs, on the **unchanged schema** (D-21). CI gets a MariaDB service to run integration tests.

## Requirements
1. `connect(&DatabaseConfig) -> Result<Pool>` (max connections from the config, connect timeout). sqlx runtime queries (`query_as` with `FromRow`), not compile-time macros.
2. `LoginRepository` methods, one per Java statement, each with `// Java: LoginController.USER_INFO_SELECT`: `account_info(login, now_ms)`, `create_account(...)`, `update_last_active(...)`, `update_last_server`, `update_access_level`, `update_tracert`, `ip_auth(login)`, `game_servers()`, `register_game_server(id, hexid, host)`, `change_password(...)`, `temp_ban(...)`.
3. Types match the schema (e.g. `lastactive` bigint ms, `accessLevel` tinyint). The `ban_temp` value is a string in the DB, compared the way the Java SQL does.
4. The password hash helper lives here: `hash_password(pw) = base64(sha1(utf8(pw)))`.
5. Integration tests run only when `L2_TEST_DATABASE_URL` is set. They create a fresh database from `sql/login/*.sql`.
