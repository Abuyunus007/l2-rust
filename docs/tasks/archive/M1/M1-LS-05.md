## Goal
Everything a registered GS sends: players entering/leaving, auth checks for players arriving at the GS, status updates, character counts, tracert, temp bans, access level and password changes. Plus the LS→GS kick and character requests.

## Requirements
1. Each handler does exactly what Java does, in the same order (e.g. PlayerAuthRequest removes the authed LS client on success).
2. ServerStatus updates the shared GS info read by the server list (status, type, brackets, max players, age).
3. ReplyCharacters feeds the waiting server-list builder (LS-03's notify mechanism).
4. ChangePassword: verify the current hash, update, reply with the same messages as Java.

- `SendMail` (0x09, ignored by Java too).
