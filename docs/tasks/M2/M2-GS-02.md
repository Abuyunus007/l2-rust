The GS side of the LS↔GS protocol: connect, key exchange, AuthRequest with hexid and host list, ServerStatus, PlayerAuthRequest/Response, PlayerInGame/Logout, ReplyCharacters, KickPlayer, reconnect loop — like Java's LoginServerThread.

## Requirements
1. Async API for the client tasks: `auth_player(account, session_key) -> bool` (awaits PlayerAuthResponse), `player_in_game`, `player_logout`, `reply_characters`.
2. KickPlayer from the LS → kicks the session (via a channel to the session registry).
3. Reconnect with Java's delay when the LS goes away; keep the online-account list and resend it like Java.
