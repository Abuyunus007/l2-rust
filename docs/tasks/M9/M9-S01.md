## Goal
Make the switch "Rust replaces Java" a safe, guided step, with a way back.

1. **Runbook** `docs/runbooks/m9-switch.md`, step by step for the owner:
   1. Prepare:
      - backup (M9-H01);
      - stop the Java game server (Sieghardt) and check that no `java.exe` game server is connected (the login server's server list shows it down);
      - write down the ports and the server id.
   2. Switch:
      - the Rust game server takes the Java server's place: `GameserverPort = 7777`, and `RequestServerID` = Sieghardt's id (2), or keep 3; the runbook explains both, including `hexid.txt` and the `gameservers` row;
      - set all `SideBySide.ini` switches to True: `DailyResetDatabaseWrites`, `ClanMaintenanceDatabaseWrites`, `MailExpiryDatabaseWrites`, `FishingChampionshipDatabaseWrites`, `CycleDatabaseWrites`, `OfflineTradeDatabaseWrites`, `SiegeDatabaseWrites`;
      - the Rust server then does every global job the Java server did.
   3. Check: the list of in-game checks after the switch (the CP lists of the earlier runbooks, short form).
   4. Way back: stop Rust, switch the settings back, restore the backup if needed, start Java.
2. **GUI "Switch to Rust" assistant** in the Setup view:
   - It walks through steps 1 to 3. Each step needs a click.
   - It writes the `.ini` changes with the in-place writer (`l2_config::ini_edit`).
   - It runs the backup first.
   - It refuses while a Java game server is still registered at the login server (ask the login server's status for its server list).
   - A "Back to side by side" button reverses the `.ini` changes.
3. **`SideBySide.ini` presets:** the assistant shows the current switch values and what the switch will change.

## Requirements
- Nothing is changed without the user's click.
- Tests: the `.ini` changes on a temp copy of `dist/`, both forward and back (byte-identical after a round trip); the refusal while a Java server is registered (fake login status).
